<objective>
Produce the multi-stage Dockerfile that packages the FastAPI backend + Next.js static export + named SQLite volume mount into a single runnable container, and wire the StaticFiles mount in `app/main.py` so the same origin serves both UI and API.

Purpose: Phase 1 success criteria #1, #4, and #5 — `docker build` succeeds, the browser shows AAPL with the flash effect at `http://localhost:8000/`, and `docker stop && docker start` is clean.
Output: `Dockerfile`, `.dockerignore`, a static-files mount in `main.py`, and a final human-verify checkpoint that confirms the visual flash effect end-to-end.

Order-sensitivity reminder: `app.mount("/", StaticFiles(html=True))` MUST be the last mount call in `main.py`. StaticFiles is a catch-all that swallows any unmatched path; mounting it before `api_router` would break every `/api/*` route.
</objective>

Create the Dockerfile at repo root:

```
# Stage 1 — Build the Next.js static export
FROM node:20-slim AS frontend-builder
WORKDIR /build
COPY frontend/package.json frontend/package-lock.json ./
RUN npm ci --no-audit --no-fund --loglevel=error
COPY frontend/ ./
RUN npm run build
# After this stage: /build/out/ holds the static export

# Stage 2 — Python runtime
FROM python:3.12-slim AS runtime
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    PIP_DISABLE_PIP_VERSION_CHECK=1 \
    UV_LINK_MODE=copy \
    UV_PYTHON_DOWNLOADS=never \
    PATH="/root/.local/bin:${PATH}"

# Install uv (Astral) once, no curl|sh tricks — pin the binary version for reproducibility
RUN pip install --no-cache-dir uv==0.4.30

WORKDIR /app

# Layer 1: copy lockfile + manifest first so dependency layer is cached when source-only edits happen
COPY backend/pyproject.toml backend/uv.lock ./backend/
RUN cd backend && uv sync --frozen --no-dev

# Layer 2: copy backend source
COPY backend/app ./backend/app

# Layer 3: copy the built frontend export from stage 1 to /app/static
# (backend/app/main.py looks at <parent of backend>/static — see _STATIC_DIR)
COPY --from=frontend-builder /build/out ./static

# Create the db directory inside the image so the named volume's mountpoint exists
RUN mkdir -p /app/db

# Expose the service port
EXPOSE 8000

# Health check uses the /api/health endpoint
HEALTHCHECK --interval=15s --timeout=3s --start-period=10s --retries=3 \
  CMD python -c "import urllib.request,sys; \
import json; r=urllib.request.urlopen('http://127.0.0.1:8000/api/health',timeout=2); \
sys.exit(0 if r.status==200 else 1)"

# Workdir for the Python process is backend/ so `app.main:app` resolves
WORKDIR /app/backend

CMD ["uv", "run", "--no-dev", "--frozen", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Critical points to validate during writing:
- The `_STATIC_DIR` constant in `backend/app/main.py` resolves to `Path(__file__).parent.parent / "static"`. Inside the container `app/main.py` lives at `/app/backend/app/main.py`, so its parent.parent is `/app/backend`. That means the static directory must be at `/app/backend/static`, NOT `/app/static`. **Adjust the Dockerfile accordingly: change `COPY --from=frontend-builder /build/out ./static` to `COPY --from=frontend-builder /build/out ./backend/static`.** And the `mkdir -p` line should reference `/app/db` (which is correct — the volume mount).
- The named volume mount target is `/app/db`. The `WORKDIR /app/backend` is for the Python process; the volume is independent of the workdir.
- `uv sync --frozen --no-dev` installs production dependencies only (skips the `[dev]` extras) using the existing lockfile — no resolution, fully reproducible.
- `--no-dev` and `--frozen` on `uv run` ensure the same env is used; alternatively, the prior `uv sync --frozen --no-dev` creates `/app/backend/.venv` which `uv run` reuses automatically.
